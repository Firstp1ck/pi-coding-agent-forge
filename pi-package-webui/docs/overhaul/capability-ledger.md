## Provenance and scope

Production source baseline: `06351edae0d87829dfa8c747d31a061825568b0e`. Integration seed: `cff3432ee63131ebb6150a906d9c06594ca2c401`. These revisions identify the requested starting point. Each scanned file also has a SHA-256 digest in `sources`, so regeneration identifies the content actually read without relying on the current branch name or commit time.

The scanner reads regular source files in this package’s `public`, `lib` and `bin` directories, the three package entry sources, the native parity JSON and the maintained [feature destination contract](feature-destinations.md). It reads no user settings, dependency tree or app/server code at runtime. Starting test paths are checked for existence, not executed by the scanner. Tests, CSS, images, sibling companion implementations, upstream Pi internals, vendor code and runtime catalogs are outside the scanner’s source walk.

## Reproduce and inspect

From the repository root, with Node 22.19 or later:

```bash
node pi-package-webui/scripts/overhaul-inventory.mjs
node pi-package-webui/scripts/overhaul-inventory.mjs --check
node --test pi-package-webui/scripts/tests/overhaul-inventory.test.mjs
git diff --check
```

`--root REPOSITORY` selects another source checkout. Without it, the script resolves its own repository root, independent of the working directory. `--output JSON_FILE` selects a JSON destination. Relative arguments resolve from the command’s working directory. Defaults write only `docs/overhaul/capability-inventory.json`. An explicit output inside the selected repository must stay in this evidence directory; an external JSON destination is also allowed. Check mode compares bytes and never overwrites stale evidence.

The walk fails on source symlinks, missing required files or owner functions, unreadable files, malformed known catalog formats, or changed canonical feature-table row count. Bounds are 256 source files, 4 MiB per file, 16 MiB total, 2,048 traversal entries and ten path components. It does not follow a dependency symlink. Catalog formats are parsed as data; no `eval`, dynamic import of production modules or server startup is used.

JSON key order and sorted record order are deterministic. There are no generation timestamps, machine paths or Git HEAD fields. A line shift changes navigation hints and source hashes but preserves named ID/symbol identities. Anonymous tag hashes and duplicate occurrence suffixes are weaker identities and require a human check when markup changes. Preserve every existing `sourceId` when adapting views.

The entrypoint retains composition, guards and the event pipeline. Refer to the canonical plan’s latest execution summary for wave acceptance and evidence; source ownership alone does not prove parity.
