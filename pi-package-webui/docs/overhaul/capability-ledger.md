# Capability migration ledger

Capability evidence for the approved compact workspace overhaul. Every legacy feature path remains active. The W0 inventory counts below describe the original baseline; the JSON inventory tracks the current source digests and locations. W1 introduces shared shell owners behind Classic and the existing mobile modes.

## Provenance and scope

Production source baseline: `06351edae0d87829dfa8c747d31a061825568b0e`. Integration seed: `cff3432ee63131ebb6150a906d9c06594ca2c401`. These revisions identify the requested starting point. Each scanned file also has a SHA-256 digest in `sources`, so regeneration identifies the content actually read without relying on the current branch name or commit time.

The scanner reads regular source files in this package’s `public`, `lib` and `bin` directories, the three package entry sources, the native parity JSON and the canonical plan. It reads no user settings, dependency tree or app/server code at runtime. Starting test paths are checked for existence, not executed by the scanner. Tests, CSS, images, sibling companion implementations, upstream Pi internals, vendor code and runtime catalogs are outside the scanner’s source walk.

## Reproduce and inspect

From the repository root, with Node 22.19 or later:

```bash
node pi-package-webui/scripts/overhaul-inventory.mjs
node pi-package-webui/scripts/overhaul-inventory.mjs --check
node --test pi-package-webui/scripts/tests/overhaul-inventory.test.mjs
git diff --check
```

`--root REPOSITORY` selects another source checkout. Without it, the script resolves its own repository root, independent of the working directory. `--output JSON_FILE` selects a JSON destination. Relative arguments resolve from the command’s working directory. Defaults write only `docs/overhaul/capability-inventory.json`. An explicit output inside the selected repository must stay in this evidence directory; an external JSON destination is also allowed. Check mode compares bytes and never overwrites stale evidence.

The walk fails on source symlinks, missing required files or owner functions, unreadable files, malformed known catalog formats, or changed canonical feature-table row count. Bounds are 256 source files, 4 MiB per file, 16 MiB total, 2,048 traversal entries and ten path components. It does not follow a dependency symlink. Catalog formats are parsed as data; no `eval`, dynamic import of production modules or server startup is used.

JSON key order and sorted record order are deterministic. There are no generation timestamps, machine paths or Git HEAD fields. A line shift changes navigation hints and source hashes but preserves named ID/symbol identities. Anonymous tag hashes and duplicate occurrence suffixes are weaker identities and require a human check when markup changes. Preserve every existing `sourceId` when adapting views.

## Integrated ownership contract

| Concern | Current owner and app adapter | Preservation contract |
| --- | --- | --- |
| Action discovery | `shell-actions.mjs`; `buildCommandPaletteItems` / `executeCommandPaletteItem` | Stable IDs, original matching/order/handlers, captured session identity/activation generation and project cwd, current catalog checked before execution |

These contracts summarize the integrated W1 modules. They do not claim W2 domain extraction or the W3 focused shell is complete. HTTP/SSE, settings/layout persistence, session lifetime and semantic extension UI remain with their existing owners. Future workers read this summary and their wave contract; earlier handoffs are supporting evidence only.

## Integration and verification limits

The focused inventory test exercises reconciliation, source/symbol identity stability under line shifts, quoted markup, data actions, computed DOM/data candidates, command/companion coverage, browser storage expressions, CLI determinism/check mode, malformed inputs, missing owners, symlinks and file-size bounds. It uses disposable source fixtures. No app module is imported or executed.

After changing any scanned source or the canonical plan, regenerate JSON and review the changed classifications and paths. The scanner’s contracts must be updated deliberately when a named function moves, a catalog format changes or a plan family is added. The ledger is a reviewed human artifact; regeneration updates JSON only. Reconcile this ledger’s matrix/counts when evidence changes. Do not rename source IDs merely to make the inventory pass.

W0-A does not run the full Node suite, browser tests, a server, performance checks, screenshots, security probes or live companion commands. W0-B owns rendered baseline evidence; the parent owns the unchanged Node suite, interface decisions, independent review and integrated W0 acceptance. No whole-wave completion, runtime parity, GUI improvement or rollout readiness is claimed.

The inventory test lives under `scripts/tests/` because it needs repository-only evidence and the canonical plan. It is run explicitly during overhaul verification, outside the npm-shipped application test suite. Moving it here avoids publishing a test whose scanner and plan dependencies are absent from the package.
