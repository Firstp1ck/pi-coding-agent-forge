Contributor-only implementation, API, architecture, testing, and maintenance information.

## Architecture

The package manifest loads `extensions/qt-webui-start.mjs` when Pi installs the package. Its `/qt-webui-start` handler passes `ctx.cwd` through the canonical `prepareLaunch()` path, spawns Quickshell with an argument array and `shell: false`, then detaches and unreferences the child so the Pi command returns without owning the window. Synchronous preparation errors and process spawn errors become bounded Pi notifications.

Three processes cooperate:

1. **Launcher** (`bin/qt-webui.mjs`, `lib/launcher.mjs`) resolves the package QML entry, the backend entry, and the CLI declared by the dependency-local `@earendil-works/pi-coding-agent` manifest, then spawns `quickshell` with an argument array, inherited stdio, `shell: false`, and the caller's working directory.
2. **Quickshell** owns the QML application. `qml/BackendBridge.qml` starts the backend with `QT_WEBUI_NODE_EXECUTABLE` and `QT_WEBUI_BACKEND_ENTRY`, writes protocol requests to its stdin, and reduces its events into QML state. QML never parses a raw Pi record and never starts Pi.
3. **Backend** (`lib/backend/main.mjs`) owns one Pi RPC child per tab through `tabs.mjs`, translates Pi records into bounded typed events tagged with the tab id, keeps a bounded transcript mirror per tab, renders Markdown, stores settings and window state, monitors portal appearance changes, lists sessions, browses directories, runs Git, sends notifications, opens links, and reaps every child on shutdown.

The Pi package exposes only import-conditioned exports, so the launcher resolves its public module with ESM resolution, walks to the matching package manifest, and uses a `createRequire` rooted there to confirm package identity. It reads the `bin.pi` declaration instead of assuming a dependency layout or searching `PATH`.

## Backend protocol (version 1)

Frames are JSON objects terminated by `\n`. Every frame carries `v: 1`. Requests flow from QML to the backend; the backend answers each request exactly once by `id` and emits unsolicited events with a monotonically increasing `seq`.

Request: `{"v":1,"id":"q-7","type":"prompt","message":"…","mode":"send","tab":"tab-1"}` — session-scoped requests may carry `tab`; without it the active tab is used. Global requests (settings, links, sequences, drafts, directories) ignore it.
Response: `{"v":1,"kind":"response","id":"q-7","ok":true,"data":{…}}` or `{"v":1,"kind":"response","id":"q-7","ok":false,"error":{"code":"busy","message":"…"}}`
Event: `{"v":1,"kind":"event","seq":42,"type":"part.render",…}`

Event payloads must not use the reserved frame keys `v`, `kind`, `type`, or `id`; `makeEvent` throws otherwise (this caught the `part.begin` `kind` collision during development).

### Events

Every event a Pi session produces carries `tab`; `backend.*`, `settings.changed`, `themes.changed`, `sessions.changed`, `events.dropped`, global notices, and `tabs.update` do not. `themes.changed` carries the same complete state as `themes_list`; QML generation checks discard older list responses before assigning the object once. `sessions.changed` carries the canonical session `path` and confirmed `settled` value after settlement persistence, or `reason: "filesystem"` when the monitor invalidates the catalog. A successful profile mutation emits `resources.changed` with `tab`, `scope`, `field`, and the full validated applied `state` for every affected tab. `tabs.update` (`{tabs, activeTab, maxTabs}`) is sent only when a summary changed, and always before the transcript replay of a newly selected tab so the client switches first; `transcript.reset` clears the tab's transcript and `transcript.row` (`row` in the client's row shape) rebuilds it, one row per frame. Session events: `backend.ready`, `backend.closing`, `backend.fatal`, `backend.backpressure`, `events.dropped`, `notice`, `settings.changed`, `pi.started`, `pi.status` (`statusKind`, `text`, `ready`, `active`), `pi.error` (empty message clears), `pi.runtime` (`provider`, `modelId`, `modelName`, `modelReasoning`, `thinkingLevel`, `sessionId`, `sessionName`, `sessionFile`, `messageCount`; emitted after every state read and after model or thinking changes, which merge into the existing session identity), `pi.exit`, `message.user` (`text`, `mode`, `attachments`: bounded file names), `message.begin`, `part.begin` (`partKind` `text` or `thinking`), `part.render` (`text`, `blocks` for text parts, `final`, `truncated`), `part.remove`, `message.end`, `tool.start` (`summary` is a bounded plain-text argument digest), `tool.update`, `tool.end` (`ok`, `durationMs`, `output`, `error`), `run.start`, `run.end` (`ok`, `aborted`), `queue.update`, `extension.request`, `extension.answered`, `extension.cancelled`, `extension.notify`, `extension.status` (`key`, `text`, and `chips`: a `setStatus` whose text is a `firstpick.git-footer-status.footer` version 1 JSON payload becomes up to 18 bounded plain-text chips from its `main` and `meta` arrays; any other JSON object with a `type` becomes its `title` as `text` and `description` as `hint`; other text stays as `text`), `composer.setText`, `window.title`.

After a backend prompt timeout, `prompt.settled` carries `requestId` (≤ 96 characters), `tab` (≤ 32 characters), `ok` (boolean), `errorCode` on rejection (1–64 characters), and `consumedAttachmentIds` (the same bounded unique-id list as prompt responses). It is emitted once when the admitted handler finally completes, even if its original timeout response has already been delivered. QML correlates it only to the matching unknown submission from the same backend/tab/session generation; it reconciles that owner's attachment list, releases the attachment lock, and never retries the prompt. A backend restart instead retires old locks and uses fresh attachment snapshots; old in-memory payloads do not survive. QML and the backend ship together, so timed-out submissions rely on `prompt.settled` or a backend restart to release their locks.

The tab registry computes `activityState` rather than leaving QML to infer it. Pending extension input during an active run has `blocked` priority, other active runs are `working`, unseen background completion is `done`, and all other open tabs are `idle`. `run.start` clears stale completion, while `tab_select` acknowledges `done`. This state is ephemeral and does not replace `statusKind` or `statusText` process-error evidence.

`part.render` is emitted at most every 80 ms per streaming part and once more with `final: true` after `message_end`, whose content is authoritative. Parts that streamed but are missing from the final message are removed.

The backend starts `session-sync` after restored paths are registered and stops it during graceful, forced, and fatal cleanup. Root and immediate-project filesystem events coalesce catalog invalidation; open paths are also stat-polled every two seconds. Both path registration and projection pass through `managedSessionPath()`, so only regular `.jsonl` files whose real paths remain under the active sessions root are read; escaping file and directory symlinks are excluded. Pi may publish a future session path before its first durable write creates the file. Registry-owned paths that fail managed validation as unavailable stay in a set bounded by the eight-tab registry and are revalidated after catalog filesystem events; they enter the monitor only after the same realpath and regular-file check succeeds. A changed path is read into an isolated copy and projected by Pi's compaction-aware `buildSessionContext()`, then converted only by `rowsFromHistory`. Semantic row comparison ignores generated row/message ids, streaming flags, live-only tool duration, and the persisted branch leaf id. Equal rows plus durable session metadata acknowledge the revision without replay. A different complete snapshot replaces the mirror, replays only an active tab, increments unread only on an inactive tab, updates persisted runtime metadata, and marks the child stale. Missing, partial, malformed, unstable, and unreadable snapshots remain pending without changing the mirror; repeated failures of one revision use exponential retry backoff from two seconds through one minute, while a new revision retries immediately. Warnings are coalesced by path, revision, operation, and error class in a 128-entry cache.

`SESSION_MUTATION_REQUESTS` is the centralized stale-write fence for prompt/steer/follow-up, sequence, rename, compaction, model, thinking, resource-state/apply, tool, skill, and sampling paths. Before dispatch, a stale tab re-enters the existing `switch_session` → `get_messages` → `get_state` flow for its current file. Concurrent guards on one tab share its serialized preparation promise, and a generation check prevents an older rebind from clearing a newer external revision. Resource transactions repeat the guard for every affected tab. Cancellation or failure leaves stale state set and rejects the requested mutation. Explicit session switch and successful new-session replacement clear it; restart retains the current path until startup resume clears it; close drops the tab and all backend reconciliation state for its now-unowned path. Projection defers while the child is active, preparing, or owned by a mutation or exclusive operation. After asynchronous loading it rechecks the pending revision, path ownership, tab generation, and busy state before applying, then retries deferred work on `run.end`, the first ready/idle status, or a later poll.

Resource mutations lock every affected tab and recheck that each is idle. Global changes target every open tab; exact-model changes target every tab currently using that provider/model. The backend reads and validates each helper state plus the latest canonical settings, applies the prospective effective profile to every target, and only then commits. Tool and skill writes call Pi Web UI's `updateWebuiSettings()` and `setExactModelProfile()` modules against the latest locked snapshot; sampling writes remain in Qt's `resources.json`. The selector submits only names in its visible inventory, and the backend supplies that inventory so `preserveUnavailableResourceNames()` retains configured names that are not currently loaded; `helperEffective()` filters the committed selection against each tab's own inventory before applying runtime state. Responses use the combined snapshot returned by the commit rather than a fallible post-commit store read. If latest-snapshot merging changes an effective selection, the backend reapplies that committed selection to each affected tab and validates the result before reporting success. An apply or pre-commit store failure rolls every attempted helper back; rollback failure is returned explicitly with an inconsistent-state warning. A post-commit reconciliation failure is reported as saved but runtime-inconsistent because the canonical commit cannot honestly be rolled back. One centralized per-tab guard fences prompts, saved sequences, compaction, Pi restart, tab close, session switch, and new-session requests until reconciliation and any rollback settle. The lifecycle handlers hold the same guard while they run, so a broader profile transaction cannot start across them either.

`lib/backend/resources.mjs` combines two ownership domains behind its asynchronous `read()`, `profileFor()`, and `update()` API. Pi Web UI's settings envelope owns nullable global and exact-model enabled-name lists, locking, latest-snapshot merges, atomic replacement, and the `PI_WEBUI_SETTINGS_FILE` override. Qt's version-2 `resources.json` owns sampling and retains legacy tool/skill values plus its earlier bounded migration marker for compatibility. The first valid legacy read migrates only canonical-null fields under Pi Web UI's lock, preserves canonical values and unrelated settings, retains all legacy data, and records migration completion in the same canonical atomic update so a failure cannot expose migrated values without the no-retry marker. Malformed, oversized, or partially invalid local data is reported and left untouched rather than being rewritten during migration. Exact-model migration and writes verify that Pi Web UI retained the requested profile within its supported bound, and in-memory model identities use unambiguous provider/model tuples while legacy slash-keyed sampling remains readable. `resourceResult()` keeps `path` as the Qt sampling file and adds `sharedPath` for the canonical settings file; diagnostics likewise retain `resources` and add `sharedResources`.

`pi-session.helperCall` observes the helper-notify promise before sending the command prompt. A helper answer wins even if it precedes Pi's prompt acknowledgement; a prompt rejection/timeout rejects and clears the helper leg; helper timeout or error clears the pending Pi command; Pi exit rejects both through their normal handlers. Successful helper answers also refresh the bounded scoped-model cache. The helper writes session tools and skills as Pi Web UI's `webui-tools-config` and `webui-skills-config` version-2 explicit/inherit entries. It reads legacy `disabledSkills` and uses a legacy `qt-webui-resources` field only when no shared entry exists; that Qt entry remains canonical for session sampling. It persists before changing in-memory state. A real append failure is returned as an error; only `sessionManager.isPersisted() === false` skips the append and returns `durable: false` with a user-facing reason.

### Remediation contracts

`request()` has a separate operation settlement hook that runs before selected-view callback filtering. An admitted prompt records its ID, origin tab, Pi generation, draft key, submitted text, mode, and attachment IDs. Client timeouts retain a bounded pending slot for late settlement. The backend-composer fixture can set `QT_WEBUI_SMOKE_PROMPT_PREFLIGHT_DELAY_MS` (1–2,000 ms) and `QT_WEBUI_SMOKE_PROMPT_TIMEOUT_MS` (10–2,000 ms) only under smoke mode, to test a handler that crosses the timeout before attachment take. Rejection retains text; acceptance clears only the matching draft revision. `draft_set.expectedText` checks the latest locked value and returns `stale_request` without changing a newer draft. `session.replaced` announces a committed switch or new session before history/runtime projection. The shell stops the old debounce, saves the outgoing key, and restores the new draft under a generation guard. First-filename promotion preserves the draft instead of treating it as replacement. Internal stale preparation sets `session.replaced.rebind: true`, so it does not supersede the originating prompt or reset its composer generation. An explicit replacement commits its path before history loading; later projection failure cannot restore the outgoing owner.

Dialog state is `open`, `submitting`, `unknown`, or terminal. The bridge retains at most 128 dialog records across tab changes. Value validation uses the announced 16,384-character limit. Only backend acceptance, `stale_request`, `extension.answered`, or `extension.cancelled` closes a pending answer. A definite rejection returns it to `open`; timeout never schedules another answer. Backend acceptance establishes a successful local Pi-stdin write, not Pi processing acknowledgement.

`selectionGeneration` travels in tab summaries, `tabs.update`, selection replays, and snapshots. Only selection events change the selected identity. `applySnapshot()` rejects every field unless both tab and generation match; hello captures its selection before its theme refresh awaits. The close-to-empty transition uses the same rule. Transcript mutations increment `transcriptRevision`; search coalesces for 60 ms, retains a `rowId`, derives its current index, and chooses the next surviving match before the previous one.

The registry reserves mutations synchronously and carries the reservation through `AsyncLocalStorage` across awaits. Nested work may reuse only its own token. Startup resume, stale rebind, explicit replacement, restart, and resource operations use this boundary. Pending external revisions force preparation before mutation even while snapshot projection is still loading; a revision observed during rebind causes another preparation, with at most three attempts before `busy`. Broader resource changes reserve every affected tab. A real-path identity index covers current and reserved saved-session paths. `tab_open` reuses its owner; `session_switch` rejects another owner with `busy` and a safe tab ID. Closing tabs retain their claims and process handles until cleanup completes. Abort, shutdown, and fatal controls do not wait for a mutation reservation. This is backend-local ownership, not cross-window locking of Pi histories.

Attachment protocol v1 remains backward-readable. The QML hello opts into `attachmentMetadata: true`; subsequent lists and snapshots omit text payloads. Clients that do not negotiate retain the legacy text field, with a 256 KiB aggregate list budget checked before mutation. Metadata contains ID, bounded name, kind, MIME type, byte size, path, edited state, and revision. `attachment_read` returns at most 32,768 characters per frame and checks revisions across at most eight chunks. Updates count UTF-8 source bytes and QML preflights the complete encoded request, including ID, tab, escaping, and newline, before admission. Add/update/remove build and budget their full result and tab snapshot before changing the store. A rejected editor remains open; an unknown outcome requires a stored-content refresh before another save.

Qt-owned `settings.json`, `state.json`, `sequences.json`, and sampling in `resources.json` share `withDocumentLock()`. util-linux `flock` locks an inherited open-file description; the parent retains it across latest-read, synchronous mutation, validation, and atomic rename. Acquisition waits at most 100 ms, with a 500 ms subprocess deadline and no application retry loop. The kernel releases dead owners without PID-reuse tests or stale-file deletion. Owner metadata is cleared on normal release. Empty 0600 `.lock` inodes intentionally remain: unlinking them could split the lock domain for waiters. Temporary write files are removed in `finally`; directories remain 0700 and documents 0600. Unknown top-level keys survive validation without becoming user settings. Full replacement of the same logical value still follows last-writer intent. No document migration is required.

`createSessionCatalog()` owns one active scan, four retained snapshots, and 512 opaque cursor entries. Candidates and project directories are deduplicated before metadata reads. Discovery caps directory entries at 4,096, candidate names at 8 MiB, readable rows at 2,000, retained row data at 8 MiB, input reads at 16 MiB, and elapsed time at three seconds. Pages have at most 200 candidate positions and 512 KiB, so invalid files still advance the legacy offset/count fields. The revision-keyed metadata cache has 512 entries and 4 MiB. Cursors expire after 30 seconds; invalidation does not mutate an existing cursor's result. A first page overtaken by invalidation returns `stale_request`. QML retries once and keeps the previous complete catalog until the replacement finishes. Legacy offset-only callers remain supported; the QML catalog always follows opaque cursors.

Production snapshot loads use two killable `snapshot-worker.mjs` workers, an eight-job queue, an 8 MiB input bound per active load, an 8 MiB result bound, a 128 MiB V8 old-heap limit per worker, and a five-second deadline including queue time. Descriptor reads count bytes after stat, with one sentinel byte for detecting growth. Pi's `SessionManager` projects an isolated copy only after that bounded read. The parent owns temporary directories and removes them after worker termination, including timeout and normal backend shutdown. Queued and completed loads recheck ownership/revision; superseded jobs never replace the view. Trusted tests can inject `filesystem`, `SessionManagerClass`, `workerUrl`, and a shorter `timeoutMs`; these are not wire or environment options. Diagnostics expose active/queued loads, reserved bytes, RSS, and cleanup failures.

### Slow consumers

Coalescable events (`part.render` before `final`, `tool.update`) are dropped above the 4 MiB or 2,000-record pressure threshold and reported through `events.dropped`. Both Pi stdout and stderr pause, including records remaining in the current JSONL batch. Ordinary requests receive `busy` before dispatch; at most 64 ordinary handlers and eight controls are admitted. Timed-out handlers retain their slot until they actually finish. Ordinary response reservations total at most 64 MiB. All producers share a hard 8 MiB / 4,096-record output ceiling, with 64 KiB reserved for closing/fatal diagnostics. Crossing a hard ceiling or failing to drain for three seconds causes one slow-consumer shutdown with exit 75. This is an explicit transport failure: accepted operations may have unknown outcomes, not replacement rejection responses. Drain resumes paused readers without losing essential records while the transport remains viable. Healthy shutdown still emits dialog cancellations. `diagnostics` reports queue peaks, admitted work, producer pauses, drops, and slow-consumer shutdowns.

## Markdown policy

`renderMarkdown` produces `heading`, `paragraph` (with `quote` flag), `code`, `listItem`, `table`, `rule`, and `notice` blocks. Inline text becomes StyledText built only from escaped text and the tags `<b>`, `<i>`, `<s>`, `<tt>`, `<br>`, and `<a href>`. Raw HTML is escaped, images become `[image: alt]` placeholders, and links keep only `http`, `https`, and `mailto` targets without credentials; other links stay as their literal Markdown. QML renders `styled` with `Text.StyledText`, code and tool output with read-only plain-text editors, and everything else as `Text.PlainText`. Link activation always goes through `LinkDialog` and then the backend's `open_link`.

Code blocks additionally carry `tokens` (`[kind, escapedText]` pairs from `highlight.mjs`, or `null` for unknown languages and oversized blocks). `MarkdownBlocks.styledCode` wraps them in `<pre>` with `<font color>` taken from `Theme.syntaxColor(kind)`; `<pre>` is required because `Text.StyledText` collapses newlines and runs of spaces outside it. The highlighted view is a `Label`, so a **Select text** toggle swaps in the plain `TextEdit`; copy uses `block.text` in both views.

## Lifecycle and process ownership

Each tab's Pi child is spawned with `detached: true` so it leads its own process group. An immutable process-owner record survives leader exit until its idempotent cleanup promise finishes. Explicit stop, restart, startup failure, and spontaneous exit share cleanup; replacement cannot start early. `terminateProcessTree` signals the group, escalates to SIGKILL after the grace period, and sweeps the group once the leader exits. Linux cleanup checks for live, non-zombie group members every 20 ms for at most one second, visiting at most 65,536 process entries per pass. It does not claim ownership of tools that deliberately leave that process group or claim to reap unrelated orphan zombies. Shutdown runs on stdin EOF (Quickshell exited), `SIGINT`, `SIGTERM`, `SIGHUP`, the `shutdown` request, and stdout `EPIPE`; the same owner stops every session watcher and poll timer before exit. Uncaught exceptions emit `backend.fatal`, synchronously initiate monitor cleanup, kill the tree, and exit 70. A relative or missing Pi entry exits 64 before starting anything.

If the backend itself is killed with SIGKILL it cannot signal anything; Pi then sees EOF on stdin and is responsible for stopping its own tool processes, which the fixture models by terminating its grandchild on `end`. `tests/backend-lifecycle.test.mjs` proves each path with a fixture grandchild (`sleep 300`).

Shutdown stops every tab (`registry.stopAll`); the forced path kills every child's process group. The state store records `activeTab: -1` for an intentionally empty selection. At startup `registry.restore()` reopens saved tabs whose folders still exist and resumes their session files once Pi is ready. The `-1` sentinel leaves them unselected. Fresh or older state keeps the previous behavior: the registry adds a tab for the launch directory when none matches and selects it. Each path emits one final `tabs.update`. The registry owns confirmed `tab.sessionFile`/`sessionName` independently of the child's volatile `pi.runtime`. Empty runtime events on startup, failed readiness, and exit clear runtime metadata without changing saved tab identity; `session.replaced` confirms a switch or new session, while a successful runtime read discovers a saved file when no resume is pending. A child-reported filename that has never existed on disk is not persisted as a durable resume target until Pi saves it; `run.end`, `pi.exit`, and external snapshot projection recheck the known filename and persist it once the file exists. Explicit switches and restored files remain durable even if subsequently deleted. Explicit restart and unexpected exit retain the confirmed file as `pendingResume`; a catalog-opened target without a confirmed file also survives exit/restart and is saved separately as `pendingResume` until Pi confirms it. After readiness the registry sends `switch_session` before permitting further persisted-session mutation; a failed/cancelled resume keeps the target and fences mutation until an explicit replacement or retry on restart. A missing file stays in saved state and receives recovery guidance instead of being mistaken for the new child's fresh session. Tab summaries, `pi.status`, and tab snapshots expose effective readiness only after resume completes, while `pi.runtime` still reports volatile child metadata. QML derives conversation identity from confirmed transitions and ready tab summaries rather than the fresh child's runtime, preserves an in-flight resource-read indicator across same-tab snapshots, and defers resource refresh until effective readiness returns; a separate `canRecover` flag in tab summaries and projected `pi.status` allows only the Sessions picker, session switch, and new session while the child is ready but its resume target is blocked. Prompts, models, and resources still use effective `ready`. Closing a tab during its registry-owned automatic resume cancels that private switch and the child instead of refusing the close as `busy`. Transition paths remain registry-private for catalog ownership and watcher registration.

Dialog cancellation commits the empty dialog map and order before emitting any `extension.cancelled` event. Subscribers may synchronously call `snapshot()` during every notification; snapshot construction still rejects a dangling dialog ID rather than hiding it. Cancellation emits each pending request ID once, and subsequent answers return `stale_request`. `tests/dialog-cancellation.test.mjs` exercises synchronous observers; backend-session tests cover one and five dialogs across exit, restart, new-session replacement, and shutdown.

In QML, the bridge treats a backend exit as an error state, fails every pending request, cancels dialogs, clears the tab list, and offers **Restart**, which starts a fresh backend that restores the saved tabs. During `Qt.quit` the bridge sends `shutdown` first and stops the process after a short grace period.

Dialogs are `Popup`s with `modal: true`, `focus: true`, an explicit initial focus item, and focus return to the composer.

Read-only readable text uses `SelectableText`, never an elided visual `Label` over separate selectable geometry. The component always renders PlainText and clips within its existing one-line or bounded wrapped geometry so drag selection, visible glyphs, and full-source Ctrl+A/C use one native `TextEdit`. Interactive completion, picker, extension-option, and tab rows use `TapHandler.DragThreshold` with a shared explicit activation function: a tap preserves the original action, while a drag selects text and emits no action. Dialog list rows that only change their highlight follow the same threshold and do not submit, pick, or navigate during selection. Action labels, icons, drag handles, and editable fields remain their existing controls.

The prompt control strip's three-line button presents a non-searchable `DropUpPicker` above the trigger. `composerMenuItems()` exposes Resources, automatic settlement with the current day value, thinking-section visibility, syntax highlighting, desktop notifications, appearance, reduced motion, Events, and Diagnostics by dispatching the existing palette actions after the popup closes; actions already visible in the window are deliberately omitted. The model and thinking buttons call `shell.openModelPicker()` / `openThinkingPicker()`, which load data through the bridge and present separate `DropUpPicker` instances above their buttons. Popup geometry stays inside `contentRoot`, arrow movement never selects, Enter/Space select explicitly, and close returns focus to the trigger. The model list uses the backend's helper-resolved Pi scope; the thinking list uses the active model's RPC levels.

`BackendBridge.orderedModelData()` applies `modelOrder` only when `scope.explicit === true`: exact saved identities still present are emitted first in saved order, then unranked models in the backend/Pi order. `saveModelOrder()` merges the complete reordered current scope before saved identities absent from that scope and truncates only after current identities have priority at `maxModels`. The backend validates, deduplicates, and stores the resulting string list. `shell.modelPickerResult()` opts into reordering only for an explicit scope with at least two rendered entries; `modelsReordered()` repeats the active-tab, picker-generation, open-popup, and item-list guards before saving. This keeps stale callbacks and synthetic partial lists from mutating the preference.

`DropUpPicker.moveItem()` copies and reassigns its source array, restores `currentIndex` by exact value, emits `reordered(values)`, and neither emits `picked` nor closes. The visible **≡** handle uses a targetless `DragHandler`; completion maps its translated row center back to a list index. `Ctrl+Shift+Up` and `Ctrl+Shift+Down` call the same move path. Both paths require the opt-in flag, at least two items, and an empty trimmed filter, preventing visible indexes from diverging from source indexes.

The bridge's `selectModel`, `cycleModel`, `setThinkingLevel`, and `cycleThinkingLevel` refuse while `active` or while a previous model/resource change is still unconfirmed, and re-selecting the current value is a no-op. Each successful response includes the backend's freshly resolved `resources`, which the bridge applies instead of guessing; tab snapshots clear resource state and issue `resources_state` for that tab. Runtime events reach the bridge before the request's response, so anything that chains a second change must wait for `modelActionPending` to clear (the smoke driver does this in `advanceModels`). `compactContext` sets `compacting` until the response arrives; the backend keeps the session busy for the same period.

`ResourceProfilesDialog` drafts one field at one explicit scope and only calls `tools_set`, `skills_set`, or `sampling_set` from **Save**. `present()` issues `resources_state`, so each opening reads Pi Web UI's latest canonical file; **Refresh** repeats that boundary without a background watcher. Tool/skill `listMode` keeps `inherit` (`null`) distinct from `custom` with an empty `listDraft` (`[]`). A custom save submits only draft names present in `visibleInventory`; the canonical updater merges retained unavailable names, so an unchanged or partially edited profile never asks the initiating helper to validate names it cannot see. Sampling sends all seven keys as a patch so blank fields remove only that scope's values; disabled fields retain their draft text and are serialized unchanged, while the backend/helper filter unsupported values from the applied provider payload. `controlsEnabled` requires available complete state, an idle Pi session, and no pending model/resource request. The dialog remains inspectable but all edits and saves fail closed while those conditions are false. `sessionDurability.durable: false` adds an alert that the active override is not saved durably, and the bridge posts the same reason after a successful non-durable session mutation. `AppDialog` returns focus to the composer.

## Launcher-to-QML environment contract

Only these launcher-owned values are passed with the `QT_WEBUI_` prefix:

| Name | Contract |
|---|---|
| `QT_WEBUI_CALLER_CWD` | Absolute caller working directory used for the backend and Pi child. |
| `QT_WEBUI_QML_ENTRY` | Absolute selected `shell.qml` path. |
| `QT_WEBUI_BACKEND_ENTRY` | Absolute backend entry (`lib/backend/main.mjs`). |
| `QT_WEBUI_NODE_EXECUTABLE` | Absolute Node.js executable used to start the backend and the Pi CLI module. |
| `QT_WEBUI_PI_CLI_ENTRY` | Absolute dependency-local Pi CLI module, read by the backend. |
| `QT_WEBUI_DEVELOPMENT_MODE` | `1` for `qt-webui dev`; otherwise `0`. |
| `QT_WEBUI_SYSTEM_COLOR_SCHEME` | Normalized XDG portal result at launch: `dark`, `light`, or `unknown`; the backend emits later valid changes. |
| `QT_WEBUI_DESKTOP_CORNER_RADIUS` | Validated non-negative Hyprland corner radius, or `unknown`. |
| `QT_WEBUI_DESKTOP_EDGE_GAP` | Validated non-negative Hyprland outer gap, or `unknown`. |

Before adding those values, the launcher removes every inherited environment key whose name starts with `QT_WEBUI_`. This prevents caller-controlled variables from activating internal test behavior or overriding launcher-owned paths. The live smoke harness can add its fixture values (`QT_WEBUI_SMOKE_MODE`, `QT_WEBUI_SMOKE_CAPTURE_PATH`, `QT_WEBUI_SMOKE_STATE_PATH`, `QT_WEBUI_THEME_MODE`, `QT_WEBUI_PI_STARTUP_TIMEOUT_MS`, `QT_WEBUI_PI_REQUEST_TIMEOUT_MS`) only through an explicit launcher test seam; the installed `qt-webui` bin never reads that seam from the environment. The backend honors `QT_WEBUI_PI_REQUEST_TIMEOUT_MS` and `debug_crash` only in smoke mode.

Path values must be non-empty, contain no NUL byte, and fit within 16 KiB when UTF-8 encoded. The backend passes the Pi CLI entry and `--mode rpc` as separate process arguments and never interpolates paths, prompts, or dialog values into shell text.

The initial `get_state` response supplies `model.provider`, `model.id`, and `thinkingLevel`; the backend copies bounded strings into `pi.runtime` events and clears them on failed state reads, restarts, and process exits so the window never presents stale runtime metadata.

Qt 6.11 registers host applications with `org.freedesktop.host.portal.Registry` during GUI startup, which can produce a non-fatal warning; the launcher defaults the child to `QT_NO_XDG_DESKTOP_PORTAL=1` while preserving an explicit caller value. The visual root explicitly belongs to `FloatingWindow.contentItem` and the surface is opaque.

## Process and failure behavior

The launcher installs handlers for `SIGINT` and `SIGTERM` only while Quickshell is active and forwards either signal to that child. It removes handlers after an error or close event. Numeric child exit codes pass through; signal exits become the conventional `130` or `143` status when applicable.

A missing Quickshell executable and a missing or malformed package-local Pi CLI both become actionable stderr messages. The launcher never falls back to a global Pi command.

## Source-checkout development

From the package directory in a source checkout, start development mode with native QML reload:

```bash
npm run dev
```

This contributor command runs the checkout's launcher and source QML. Installed users should use `qt-webui dev` instead.
