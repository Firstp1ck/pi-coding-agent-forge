# Source selection and freshness

Use the smallest source set that can directly address the request.

## Priority

1. Local authoritative files and documentation for the installed system.
2. Official version-matched documentation and primary sources.
3. Peer-reviewed, standards, or regulator sources when the question requires them.
4. Reputable secondary sources.
5. Community material, labeled as such and not the sole support for high-risk claims.

Authority, relevance, and freshness are separate checks. A prestigious source that does not support a claim is not support for that claim.

## Passage discipline

- Prefer a short exact passage that directly bears on one claim.
- Keep a stable source identifier, locator, retrieval time, and location within the source.
- Deduplicate canonical URLs and overlapping excerpts before selecting passages.
- Fetch a decisive source when a search snippet omits the needed wording.
- Treat snippets as provisional when the complete source could change the conclusion.

## Explicit freshness

Only enforce recency when the task explicitly requires it. Record both:

- a maximum age in days; and
- the date basis: publication time or retrieval time.

A publication-time policy requires a publication date. Do not substitute retrieval time. A retrieval-time policy requires a retrieval date. Missing dates, future dates, or dates older than the bound are unresolved evidence, not a reason to guess.

Without an explicit policy, describe a source as dated or undated when relevant, but do not claim it is current.
