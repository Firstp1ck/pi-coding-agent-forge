Project request: $@

1. Read the applicable project instructions and inspect the workspace. For a new project, identify the intended user, first usable outcome, and constraints that affect the design. For an existing project, trace the affected behavior and check the working tree. When resuming, find the relevant active plan or issue, verify its last milestone against the current work, and continue from the first unfinished step. If the goal is still unclear, ask one focused question.
2. State what observable result will count as done. Apply the shared architecture guidance where relevant. If a requirement carries a material cost, explain the consequence and recommend an alternative. Handle routine choices within the agreed design.
3. Follow the path that fits the request. For a new capability, use the available feature-development-workflow skill and its lightweight or complex path. For a defect, follow the available fix workflow and recheck the original symptom. For a refactor, identify and preserve the behavior callers rely on. For design or planning alone, deliver the recommendation, trade-offs, and verification approach. For other work, follow the applicable repository workflow.
4. Verify implemented changes through their normal entry point and run the relevant checks. Report the result and any unverified behavior. For work spanning sessions, keep the last verified result and next unfinished step in one active plan. Follow the project's plan lifecycle and archive the plan after verifying completion. A small completed change needs only a brief report.
