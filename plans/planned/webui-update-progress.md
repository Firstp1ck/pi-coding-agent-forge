# Update progress and unchanged feedback

Authorized 2026-11-15, baseline 06657bad. Parent owns integration. Complex: backend job snapshots cross into browser progress UI. Preserve the user's one Sol/high worker and one fresh Sol/high reviewer per task. Two independent tasks below, no extra review rounds.

## Outcome and decisions

Updating must give visible feedback even after the menu closes. Show a compact persistent progress card near Updates, with current command step, elapsed time, live bounded output and an explicitly estimated percentage. Estimates reflect elapsed time within each sequential command, never represent downloaded bytes or measured work, stay below 100 while running, and stop animating on failure/unknown. Only successful terminal results reach completion. Do not add version checks or change update commands, discovery, auth, confirmation, concurrency, timeout or restart policy.

Recognize Already up to date only from explicit successful command output. Pi self: `pi is already up to date (v...)`; targeted extension: exact package source `npm:@firstpick/pi-package-webui is already up to date`; all: both Pi self and `Packages are already up to date`. npm global: standalone npm summary `up to date[, ...] in ...`, with no contradictory added/removed/changed summary. Nonzero/timeout/warning/skipped/contradictory/unknown output must never become an unchanged success. Unknown successful output says commands completed. No restart recommendation if every command explicitly unchanged. Mixed outcomes report per-command facts.

No blocking questions. Evidence for messages inspected read-only in installed Pi dist/package-manager-cli.js and npm lib/utils/reify-output.js; do not execute installed commands. No new dependencies.
